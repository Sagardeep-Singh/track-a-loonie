# Paid plan with a free tier: test plan (tester pass)

Written before implementation, per `CLAUDE.md` Agent Workflow step 4. This is the acceptance bar senior-developer implements against. It contains no test code. Companions: `paid-plan-free-tier.md` (scope and locked decisions) and `paid-plan-free-tier-architecture.md` (design). Section numbers like "arch s5" refer to the architecture doc.

Conventions inherited from the repo, to be followed exactly:

- Unit tests live in `tests/unit/services/`, `tests/unit/lib/` and `tests/unit/validators/`. Vitest runs `tests/unit/**/*.test.ts` in the `node` environment (`vitest.config.ts`).
- Prisma is mocked with `vi.hoisted` plus `vi.mock('@/lib/db/prisma', () => ({ prisma: prismaMock }))`, then `await import(...)` of the module under test, as in `tests/unit/services/reminders.test.ts` and `emailVerification.test.ts`.
- Interactive transactions: `prismaMock.$transaction = vi.fn(async (fn) => fn(prismaMock))`. Assert on the same mock whether a call went through `tx` or the top-level client. Where the architecture says "in one transaction", also assert that `$transaction` was called and that the writes happened on the `tx` argument, not on a separate client. Make `tx` a distinct object that wraps the same fns if a test needs to prove this.
- Transport seams are mocked at module level, never at the network. `@/lib/push/webPush` is mocked as `{ isPushConfigured, sendPush }` (reminders). Add `@/lib/billing/stripe` the same way (see Billing). Email is mocked at `@/lib/email/brevo` (`sendEmail`, `isEmailConfigured`).
- Fixed clock: always pass `now` explicitly (all new entitlement functions take it). Use `vi.useFakeTimers` only where a function reads `Date.now()` internally. Use `const NOW = new Date('2026-03-10T13:00:00.000Z')` plus `DAY = 86_400_000`.
- Env-var tests: set and restore `process.env.*` in `beforeEach`/`afterEach`. Never leak `STRIPE_SECRET_KEY`, `TRIAL_HASH_KEY` or `ALLOWED_SIGNUP_COUNTRIES` between tests. Stub with `vi.stubEnv` and `vi.unstubAllEnvs()`.
- `tests/unit/lib/auth-actions.test.ts` mocks `next/headers` as `{ headers: headersMock }` and resolves `new Headers({...})`. Country tests reuse that shape (`headersMock.mockResolvedValue(new Headers({ 'x-vercel-ip-country': 'US' }))`). The `redirect` mock throws a signal class, so assert on that, not on a return value.
- Money: no new money arithmetic in this feature. Prices live in Stripe. The money-relevant surface is the existing Decimal handling around the gates (see the transactions gate cases: a gated create must not mutate or serialize amounts differently from today). Add at least one regression assertion per gated create/update that the returned `amount` is still a string.

## 3. Adversarial and boundary cases (cross-cutting)

Add these as explicit cases (grouped by owner file above, repeated here for the reviewer):

- **Empty and malformed input:** empty string/whitespace/no-`@` emails in `normalizeEmailForTrial`; empty `googleSub`; empty `userIds` in `listUserIdsWithFeature`; malformed or oversized webhook body (signature valid but JSON invalid: `constructStripeEvent` throws a typed error, route returns 400 not 500); checkout body `null`, array, extra keys; `x-vercel-ip-country` of `''`, `'  '`, `'ca'`, `'XX'`, `'CA\n'`, multiple values `'CA, US'`; `ALLOWED_SIGNUP_COUNTRIES` of `' '`, `'CA,'`, `'ca'`.
- **Boundary values:** trial day 0/29/30/31 incl. ms edges; `trialDaysLeft` ceil at 29.0001 days; 49h vs 48h `trial_end`; 730-day claim retention boundary (`lt` not `lte`); trial-email window at 25d/24d/30d; account limit at 1/2/3; `statementDay` 1 and 28 to 31 (and the truthiness trap for any value); `take: 200` cap with exactly 200 and 201 candidates.
- **Money:** gates must not alter string serialization of `amount`/`startingBalance`; no float math introduced; price ids only from env (no hard-coded amounts in code: assert the code never contains `4`/`40` price amounts by test of param shape).
- **Month rollovers:** `trends` with `range: 6/12` crossing a year boundary still returns the correct months for entitled users; `trialEndsAt` across month ends (Jan 31 start), leap day (`2028-02-29` start), and DST.
- **userId scoping:** every new query (`account.count`, `subscription.findUnique`, `user.findMany` in candidates, checkout and portal lookups) filters by the requesting user; test that a second user's data never influences the first (two-user fixtures where user B is paid and user A free, and vice versa); plan checks run only after the ownership not-found checks so a free user cannot probe other users' resources through plan errors (not-found beats plan-required).
- **No raw model leakage:** `getPlanSummary`, `createUser`, `findOrCreateGoogleUser` return plain objects; deep-key checks exclude `stripeCustomerId`, `stripeSubscriptionId`, `passwordHash`, `emailHash`, `googleSubHash`.
- **Concurrency notes (unit-simulated, not truly concurrent):** two `startTrialInTx` calls for aliases (`createMany` count 1 vs 0); duplicate webhook delivery (second `StripeEvent.create` raising P2002); two token consumptions; two cron runs claiming the same trial email (`updateMany` count 0 skips); two checkouts sharing the customer idempotency key. Accepted, documented non-goals: count-then-create for the account limit can allow a 3rd account under a race, and two Checkouts can create two subscriptions.
- **Secrets and logs:** no test should print `TRIAL_HASH_KEY`, Stripe keys or webhook secrets; assert error messages thrown by billing code contain neither the key values nor raw Stripe error bodies.
- **No em dashes** in any user-visible copy introduced (plan messages, emails, deletion notice), as a simple string assertion in the message-map test.

## 4. Gaps and contradictions found between the docs and the code

All resolved on 2026-10-05 unless marked open. Resolutions are reflected in the tables above and in the architecture doc.

1. **Billing on without `TRIAL_HASH_KEY`.** Resolved: required, production boot fails (decision 7, test 1.7a). The "key unset" trial case only happens with billing off.
2. **`createUser` and email not configured.** Resolved: billing requires Brevo (decision 6). The `createUser` trial branch is dropped; verification, password reset and Google are the only trial paths.
3. **Reimbursement link edits and import.** Resolved: editing is gated (decision 2), import bypasses gates (decision 3).
4. **`trialStatus` and `trialDaysLeft` for billing off and paid-during-trial.** Resolved in arch s5: billing off is all null; paid during trial keeps `trialStatus: 'active'` and `trialEndsAt`, with `trialDaysLeft` null.
5. **Reminder gate and `skippedNotEntitled`.** Resolved: the schema always sends `enabled`, so any save with `enabled: true` is gated. `skippedNotEntitled` counts only due users who were skipped.
6. **Cron failure semantics.** Resolved: 500 when any job rejected, partial summaries kept, failed keys are `{ error: true }`.
7. **Trial email window.** Resolved: `gt now - 30d`, `lte now - 25d`. A user missed by 5 failed runs gets no email; accepted.
8. **Account deletion ordering.** Resolved by the outbox: Stripe is only called after the DB transaction commits, and failures are retried by the cron.
9. **`customer.deleted` wording.** Resolved: the architecture says it's deliberately not subscribed.
10. **Trialing checkout with a non-Canadian card.** Resolved: cancelled with no refund, plus the country email (decision 5).
11. **Non-card payment methods.** Resolved: `payment_method_types: ['card']`.
12. **`expires_at` margin.** Resolved: 31 minutes.
13. **PAUSED, UNPAID and INCOMPLETE checkouts.** Resolved: 409 for PAUSED and UNPAID; INCOMPLETE cancels the stale subscription and continues.
14. **Normalization fallbacks.** Resolved: an empty local part or a missing `@` returns the trimmed, lowercased input.
15. **HMAC domain separation.** Resolved: emails are hashed as `'email:' + normalized`, Google ids as `'google:' + sub`.
16. **2 years vs 730 days.** Resolved: code uses 730 days, copy says "up to 2 years".
17. **`allowedSignupCountries` fails open on typos.** Resolved: a set value with no valid code refuses everyone and logs an error.
18. **Header access in the `signIn` callback.** Open, implementation-time check: confirm `headers()` works inside an Auth.js callback against the Next 16 docs. The new-user lookup uses `normalizeEmail`.
19. **Google email case.** Resolved on `main` by #92: `findOrCreateGoogleUser` normalizes the email.
20. **`updateAccount` statement day comparison.** Covered by the tests in 1.6: compare with the stored value, `undefined` means no change.
21. **E2E infrastructure.** Open, implementation-time: (a) a second dev server on another port sharing `.next` is likely to conflict (see 2.1); (b) `reuseExistingServer` means a hand-started dev server silently ignores the new env; (c) the Brevo fixture only returns the last email, which races under `fullyParallel`; (d) the verification helper is new work (the password reset spec from #92 has a reusable email-link pattern); (e) `TrialClaim` rows persist across runs by design, so trial-already-used specs need fresh addresses each run; (f) the seeded `dev@example.com` has no trial, so billing stays off for the base project; (g) the billing project needs dummy Brevo and `TRIAL_HASH_KEY` values or the boot check refuses to start a production build.
22. **`/pricing` with billing off.** Resolved: 404.
23. **Unknown Stripe status or missing `items.data[0]`.** Resolved: throw, so Stripe retries.
24. **Doc drift.** Resolved: the Trends range gate moved to `trends.test.ts` in the product doc. The ui-designer spec is still pending, so the e2e selectors in section 2 must be reconciled with it.
25. **Deletion depending on Stripe.** Resolved: deletion is never blocked (decision 9 in arch s9).
26. **New since these docs were written.** Password reset verifies email and now starts the trial (1.4). Zero-based budgeting is free and needs no gate. The app is now called Track a Loonie, so user-facing copy and idempotency key prefixes (`tal-`) changed.
